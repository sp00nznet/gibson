# Contributing

Issues and pull requests are welcome. GIBSON's priority is cool first, practical second, so a
new world, a better synth patch or a sharper NYX line is as welcome as a bug fix.

## Before you open a pull request

1. `npm install`, then `npm test` passes (`check: all passed`).
2. If you changed anything visible, regenerate the screenshots with `npm run shots` and look at
   them. Shot mode runs offscreen in a demo folder, so it shows nothing of your machine.
3. Add a line under `## [Unreleased]` in [CHANGELOG.md](CHANGELOG.md).
4. If you changed how the parts fit together, update [docs/architecture.md](docs/architecture.md).

Keep pull requests to one change each. Say why in the description, not just what.

## Where your code comes from

GIBSON is MIT. Contributions must be your own work or come from MIT-compatible sources, with
the original licence notice kept. Do not port code from GPL, LGPL, AGPL, MPL or unlicensed
projects (terminal emulators and demoscene players are the likely ones to have open), and do not
write "our own version" with their source open beside you: that is still a derived work. If you
copy permissively licensed code, say where it came from in the pull request.

Audio and art must be generated by the code in this repository or carry a licence that allows
redistribution; add a row to [PROVENANCE.md](PROVENANCE.md).

## A note on AI-assisted contributions

Welcome, as long as a person has read, understood and tested the change. The pull request is
yours, and so are the answers to review questions.

## Security problems

Do not open a public issue; see [SECURITY.md](SECURITY.md).
